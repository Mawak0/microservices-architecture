# Олимпиадная платформа

Сервисы размещаются независимо:

| Каталог | Назначение |
|---|---|
| `services/materials/` | Бланки, комплекты и печатные материалы |
| `services/intake/` | Приём фотографий бланков |
| `services/review/` | Проверка ответов и апелляции |

В каждом каталоге собственные `src/`, `tests/`, `contracts/`, `SERVICE.md`,
`README.md`, solution и настройки сборки. Команды README выполняются из каталога
сервиса. Общие исходники не копируются в корень и не перезаписывают соседний сервис.

Первоначальный общий тестовый стенд сохранён в `legacy/contract-baseline/` для
истории; это не реализация сервиса и он не включён в CI новых сервисов.

## Последовательная проверка

Подготовительный PR структуры → шесть PR каждого сервиса. Первый PR каждого
сервиса основан на подготовительной ветке, следующие — на предыдущем PR своего
сервиса. После слияния предшественника базовую ветку следующего PR переводят на
`main`. До этого diff показывает только один шаг, а не всю реализацию.

`node tools/review-ci.mjs <service>` собирает и проверяет доступную часть сервиса.
До добавления HTTP-приложения запускаются тесты уже реализованных правил;
полный исходный приёмочный набор обязателен на последнем шаге. Он не ослабляется.

Экспорты актуальных бизнес-правил Event Storming находятся в
`docs/event-storming/`; источником служит связанная Figma-доска, а не перерисовка.
