# Сервис проверки ответов и апелляций

Владеет делом ответа, расшифровкой, вердиктами, апелляцией, общей квотой игры и
контролем полноты проверок. Не принимает новые фотографии, не печатает бланки,
не начисляет баллы и не завершает сам турнир.

## Сущности и границы

- `AnswerCheck`: одно дело на receiptId, снимок, команда/игра/бланк, вручную
  введённые taskId/transcription, назначение, исходный и текущий вердикты, история.
- `Appeal`: часть жизненного цикла существующего дела, без новой фотографии.
- `GameAppealQuota`: общий лимит конкретной игры для всех команд; атомарный допуск
  апелляции вместе с расходом 1 и резервированием ключа teamId + gameId + taskId.
- `GameReviewCompletion`: manifest принятых ответов конкретного цикла и контроль
  завершения каждого дела/апелляции. Может быть process manager, а не богатый агрегат.
- Очередь — представление дел, не самостоятельный агрегат.

## Назначение и вердикт

Проверяющий выбирает следующую работу одним запросом `/checks/next` или берёт
конкретное дело. Одновременно у дела только один исполнитель. Чужой активный
исполнитель не может сохранить вердикт. Явный release возвращает работу в очередь.
Автоматическое восстановление после падения проверяющего потребует согласования
lease/timeout; конкретное число секунд пока не задаётся.

Номер задачи и ответ читаются вручную. TaskId должен принадлежать игре. Контракт
фиксирует введённую расшифровку и вердикт; он не требует OCR. Исходный вердикт не
перезаписывается при коррекции; текущий вердикт и revision меняются, история остаётся.
После дедлайна продолжается проверка ранее принятых ответов. Задержанная доставка
`ReceiptAccepted` не становится новой сдачей и не отбрасывается из-за текущего срока.

## Апелляции

Наблюдатель по просьбе участника подаёт reason + checkId после исходного вердикта.
В домино запрещено; срок подачи должен быть открыт; квота — одна на игру.
Повторное обращение запрещено по teamId + gameId + taskId, даже через другое дело
и даже после возврата использования. Проверяющий видит исходный вердикт и снимок.

`upheld` сохраняет решение, не возвращает квоту. `jury-error-corrected` одновременно
фиксирует исправленный вердикт/расшифровку и возвращает 1 ровно один раз. Признание
ошибки без исправленных данных не допускается как завершённый исход. Исправление
может менять расшифровку без изменения correct/incorrect; это не обязательно
изменяет баллы. Ручная коррекция администратора не является апелляцией и сама по
себе не возвращает квоту.

Для интеграции публикуются `AppealOpened`, `AppealResolved`, `VerdictCorrected`.
Внешняя публичная таблица показывает ожидание и отдельно изменение **баллов**.
Этот сервис не решает цвет «баллы изменены»: это известно только после оценивания.

## Полнота

`complete=true` означает готовность проверок для **текущего** cycleId, а не
завершённую игру. Требуются: manifest получен, все его receiptIds доставлены,
все дела имеют решение, нет незавершённых апелляций и окно допустимых апелляций
закрыто (для домино апелляций нет). Дедлайн завершения игры дополнительно проверяет
владелец игры. Старый manifest не может закрыть текущий цикл.

## Ошибки

`UNAUTHENTICATED`, `FORBIDDEN`, `CHECK_ALREADY_ASSIGNED`, `CHECK_NOT_ASSIGNED_TO_YOU`,
`TASK_NOT_IN_GAME`, `CHECK_NOT_REVIEWED`, `APPEAL_NOT_ALLOWED`, `APPEAL_DEADLINE_PASSED`,
`APPEAL_ALREADY_USED`, `APPEAL_QUOTA_EXHAUSTED`, `APPEAL_ALREADY_RESOLVED`,
`CORRECTION_REQUIRED`, `CYCLE_MISMATCH`, `IDEMPOTENCY_KEY_REUSED`, `VALIDATION_ERROR`.

## Зависимости и оставшиеся проверки

Контракты тестовых соседей — `test-support/README.md`. Входящие события приёма
описаны отдельно в `contracts/intake-events.schema.json`; это копия контракта
производителя, которую необходимо менять согласованно с веткой intake.
Транспорт событий в тестах HTTP, production-брокер не предписан.

Не покрыты аварийный перезапуск БД/процесса, автоматический lease recovery,
алгоритмы начисления баллов и цвет реального UI. Последние два относятся к другим
сервисам. Правила обработки неразборчивого текста уже принятого снимка пока
не согласованы — тесты не выбирают за заказчика вердикт в этом случае.
