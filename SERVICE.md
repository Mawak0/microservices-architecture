# Сервис приёма бланков

Владеет фактом приёма и сохранённым снимком, не реестром выпущенных QR и не
вердиктом. Агрегаты-кандидаты: `Receipt` и `IntakeSession` (игра + cycleId).

## Сценарий

1. Администратор/технический обработчик открывает сеанс по актуальной игре.
2. Наблюдатель сканирует QR одновременно с фотографированием и подтверждает
   чёткость. Нечитаемый бумажный бланк не принимается.
3. Сервер проверяет подлинность QR через материалы, принадлежность по реестру,
   допуск команды, открытый сеанс и актуальный срок сдачи.
4. Сохраняет фото и факт приёма; только затем возвращает 201 с квитанцией.
5. Надёжно передаёт `ReceiptAccepted` на проверку. Недоступность проверяющих
   не отменяет уже сохранённый ответ.
6. После закрытия приёма фиксирует полный список receiptIds и публикует
   `IntakeClosed`. Этот список включает ответы, события которых ещё в доставке.

Один зарегистрированный бланк принимается один раз, в том числе при параллельных
запросах. Данные команды/игры из клиента не являются доверенным источником.
Номер задачи и текст ответа не распознаются сервисом приёма.

## Предложенный транспорт

Для небольшого исполняемого контракта фотография передаётся как Base64 в JSON.
Это **не окончательное решение по большим файлам**; multipart/pre-signed upload
можно выбрать позже с сохранением бизнес-семантики подтверждения приёма.
API не реализует камеру; UI обязан получить реальное подтверждение наблюдателя.
Флаг `legibilityConfirmed` не заменяет автоматическую криптографическую проверку QR.

Ошибки: `UNAUTHENTICATED`, `FORBIDDEN`, `INVALID_QR`, `LEGIBILITY_NOT_CONFIRMED`,
`INVALID_IMAGE`, `VALIDATION_ERROR`, `BLANK_ALREADY_ACCEPTED`, `INTAKE_CLOSED`,
`TEAM_NOT_ADMITTED`, `STORAGE_UNAVAILABLE`, `IDEMPOTENCY_KEY_REUSED`,
`CYCLE_MISMATCH`, `DEADLINE_NOT_REACHED`.

PUT открытия идемпотентен и никогда не открывает уже закрытый cycleId заново.
Неявного открытия после закрытия турнира нет. Смена цикла конкретной игры требует
нового решения внешнего владельца игры; окончательный бизнес-процесс ещё открыт.
Закрытие сеанса после дедлайна доступно admin/integration, а не наблюдателю.

## Зависимости и границы покрытия

Стенд заменяет авторизацию, игры, команды, материалы, хранилище фотографий и
транспорт событий; адреса — `test-support/README.md`. Приём не ждёт HTTP-ответа
сервиса проверки, который подтверждал бы готовность людей проверять работу.
Права checker на чтение квитанции/снимка нужны для проверки; organizer/гость
их не получают. Ссылки на изображения должны быть защищены в production.

Тесты проверяют HTTP-поведение, гонки запросов, ошибку хранения и временный отказ
доставки. Они не доказывают сохранность после аварийного завершения процесса:
после выбора БД нужны crash/restart-тесты. Также нужны UI-тесты камеры и проверки
читабельности реального изображения. Отсутствие реализации не скрывается skip.
