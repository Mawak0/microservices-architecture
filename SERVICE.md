# Сервис проверки ответов и апелляций · контракт 0.2

Сервис владеет делами ответов, вердиктами, апелляциями, общей квотой игры и
контролем полноты проверок. Он не печатает бланки и не начисляет баллы.

## Проверка одной кнопкой

ReceiptAccepted содержит taskId/taskNumber из доверенного реестра бланков.
При загрузке/назначении дела сервер получает referenceAnswer из библиотеки задач.
Проверяющий видит снимок, номер задачи и эталон; отправляет только verdict:
correct или incorrect. Нет поля для ввода ответа, номера задачи или OCR.
Нечитаемый текст ответа проверяющий оценивает как incorrect. Неподлинный или
нечитаемый QR должен был быть отклонён при приёме.

Эталон доступен только через защищённый интерфейс проверки, не публичному гостю
или организатору команды. Клиент не может подменить taskId, эталон или расшифровку.
Исходный вердикт и история сохраняются при пересмотре. Ранее принятые ответы
доставляются и проверяются после дедлайна.

## Агрегаты

- AnswerCheck — одно дело на receiptId, назначение, исходный/текущий вердикт, история.
- Appeal — пересмотр того же дела/снимка.
- GameAppealQuota — единый лимит игры, расход/возврат и ключ teamId+gameId+taskId.
- GameReviewCompletion — полнота по всему накопленному набору ответов игры.
Очередь — представление дел, а не агрегат.

Одна активная проверка у дела; явный release освобождает назначение.
Автоматический возврат после разрыва соединения требует решения по аренде.
Для апелляций путь восстановления назначения также нужно согласовать.

## Апелляции

Разрешённость берётся из capabilities.appealsAllowed, а не имени игры.
Текущий профиль домино: false. Новые типы игр поддерживаются данными профиля.
Нужны исходный вердикт, открытый срок подачи и доступная общая квота.
Одно задание команды обжалуется один раз, даже через другое дело.

upheld сохраняет вердикт без возврата квоты.
jury-error-corrected требует фактически изменённого вердикта, сохраняет его и
возвращает одно использование ровно один раз. Тот же вердикт — VERDICT_UNCHANGED.
Повторная апелляция после возврата всё равно запрещена.
Административная коррекция не является апелляцией и сама квоту не возвращает.
Исходный вердикт остаётся виден проверяющему апелляции.

## Повторное открытие и полнота

Повторное открытие — lateSubmissionAllowed у той же игры, не новый цикл.
Бланки, дела, квота, запрет повторного обжалования и история не сбрасываются.
Техническая admissionVersion меняется с режимом приёма; это не бизнес-цикл.

complete=true требует актуального закрытого приёма, manifest текущей версии,
доставки и проверки ВСЕХ перечисленных ответов, рассмотрения апелляций и
невозможности новых допустимых апелляций. При lateSubmissionAllowed=true
завершение невозможно даже при отсутствии текущей очереди.
После повторного закрытия manifest включает старые и поздние ответы.
Старый manifest подтверждается без повторного эффекта, но не завершает актуальную
версию. Владелец игры проверяет admissionVersion перед применением AllChecksCompleted.
Дедлайн завершения игры проверяет внешний владелец игры.

## Контракты и ошибки

Входящий contracts/intake-events.schema.json идентичен контракту производителя.
События вердиктов не содержат серверный эталон. События апелляций позволяют
публичному слою показать ожидание; изменение баллов определяет сервис оценивания.

Ошибки: UNAUTHENTICATED, FORBIDDEN, CHECK_ALREADY_ASSIGNED,
CHECK_NOT_ASSIGNED_TO_YOU, CHECK_NOT_REVIEWED, APPEAL_NOT_ALLOWED,
APPEAL_DEADLINE_PASSED, APPEAL_ALREADY_USED, APPEAL_QUOTA_EXHAUSTED,
APPEAL_ALREADY_RESOLVED, CORRECTION_REQUIRED, VERDICT_UNCHANGED,
IDEMPOTENCY_KEY_REUSED, VALIDATION_ERROR.

Открытые технические решения: crash/restart-тестирование, восстановление назначения,
фиксация версии эталона при его административном изменении. Сервиса здесь нет.
