# Приём бланков: регрессия перезапуска и покрытие

## Ошибка проверки перезапуска

В `scripts/restart-probe.mjs` проверка ожидала одно сообщение о принятом ответе,
но иногда получала пустой список (`0 !== 1`). После остановки процесса сообщение
может оставаться назначенным прежнему отправителю на 30 секунд. Это сохранённое
ограничение защищает одновременную отправку несколькими процессами.

Особенно важна остановка во время отправки: отмена не подтверждает доставку и не
удаляет сообщение, но назначение остаётся до своего срока. Прежняя проверка ждала
только 10 секунд, поэтому зависела от момента остановки процесса. Успешный push
и упавшая PR-проверка могли проверять один код с разным порядком выполнения.

Теперь после перезапуска проверка продвигает управляемые часы стенда на 31 секунду.
Срок назначения истекает без долгого ожидания реального времени. Проверки сохранённого
ответа, прав, повторной сдачи и доставки ровно одного сообщения сохранены.

Добавлены отдельные проверки:

- новый процесс не может отправить сообщение до истечения назначения;
- после истечения назначение восстанавливается с прежним идентификатором события;
- отмена отправки не теряет сообщение;
- временная ошибка доставки повторяется после задержки, без изменения события;
- сам сценарий перезапуска обязательно использует управляемые часы стенда.

## Покрытие на 6 ноября 2026 года

Сопоставимое исходному CI измерение по всем четырём сборкам сервиса:

| Слой | Покрытые строки | Всего строк | Покрытие |
|---|---:|---:|---:|
| Domain | 77 | 84 | 91,67% |
| Application | 170 | 172 | 98,84% |
| Infrastructure | 235 | 249 | 94,38% |
| API | 146 | 162 | 90,12% |
| **Всего** | **628** | **667** | **94,15%** |

До добавления тестов CI показывал 441/667, или 66,12%. Область измерения не сужена:
API, фоновые обработчики и настройка зависимостей не исключаются. Отчёт не включает
сами тесты, JavaScript-стенд и внешние библиотеки. Количество покрытых строк в фоновых
обработчиках может незначительно зависеть от порядка остановки тестового приложения.

81 .NET-тест включает настоящие HTTP-запросы через `WebApplicationFactory`,
проверку авторизации, JSON, ключей повторных запросов, QR-фотографий, чтение принятых
ответов, позднюю сдачу, полный список при закрытии и преобразование ошибок в ответы API.
Используются настоящие маршруты, middleware, прикладные сценарии, декодер QR и SQLite;
заменяются только внешние системы. Также проходят 30 неизменённых исходных приёмочных
сценариев, перезапуск реального процесса и 13 проверок документов/стенда.

В CI сохранены Summary и артефакт `coverage-and-test-results` с Cobertura XML и TRX.
Сборка завершается ошибкой, если общий процент меньше 90 или в отчёте отсутствует
хотя бы одна из четырёх сборок сервиса. Результаты локального измерения не заменяют
результат конкретного запуска GitHub Actions.

## Повторение измерения

```powershell
dotnet build Sapientum.Intake.sln --configuration Release
dotnet test Sapientum.Intake.sln --configuration Release --no-build --collect:"XPlat Code Coverage" --results-directory TestResults --logger "trx;LogFileName=tests.trx" -- DataCollectionRunSettings.DataCollectors.DataCollector.Configuration.Format=cobertura 'DataCollectionRunSettings.DataCollectors.DataCollector.Configuration.Include=[Sapientum.Intake.*]*'
npm test
npm run test:service
```

Для сравнения используйте отчёт одного прогона, а не смесь старых и новых измерений.
В CI каждый запуск получает чистый каталог. Исходные тесты `tests/acceptance.test.mjs`
не изменялись; новые .NET HTTP-тесты находятся в `tests/Sapientum.Intake.Tests/ApiTests.cs`.
