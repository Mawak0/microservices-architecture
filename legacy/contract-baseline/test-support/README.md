# Заглушки внешних зависимостей (НЕ реализации сервисов)

`npm run fixtures` запускает in-memory HTTP-сервер только на loopback.
Данные исчезают при остановке. `FIXTURE_PORT` меняет порт (по умолчанию 19100).
Нельзя разворачивать этот стенд в production: тестовые управляющие маршруты
намеренно не имеют авторизации.

Будущему сервису нужны адаптеры следующих контрактов. Названия его переменных
окружения не навязываются — адреса адаптеров настраиваются в реализации.

| Метод и путь | Назначение |
|---|---|
| `POST /auth/introspect` `{token}` | `{active,userId,roles}`; тестовый провайдер идентификации |
| `GET /games/{id}` | Система, cycleId, состояние, сроки, настройки комплекта, taskIds |
| `GET /teams/{id}` | Команда, допуск к игре |
| `GET /tasks/{id}` | Условие и эталон (только для доверенного адаптера) |
| `POST /blank-verifications` `{qrToken}` | Проверенный бланк или 422 `INVALID_QR` (для приёма) |
| `GET /receipts/{id}` | Уже принятый ответ для восстановления доверенных данных проверки |
| `POST /images` `{receiptId,blankId,dataBase64,mediaType}` | Сохранить снимок, ответ `{imageRef}`; может вернуть 503 |
| `GET /images/{id}` | Сохранённые байты снимка |
| `POST /events` | Приёмник конвертов событий; может вернуть 503 для теста повторной доставки |

Эталоны находятся в защищённом контракте библиотеки, не в публичном API материалов.
Тестовые провайдеры не реализуют ни печать, ни приём, ни проверку, ни квоты.

Токены: `test-admin`, `test-observer`, `test-checker`, `test-checker-2`,
`test-organizer`, `test-multi` (наблюдатель + проверяющий), `test-system`
(техническая идентичность, не новая пользовательская роль).
В production должна использоваться реальная проверка доверия.

## Управление сценариями (только тестовый стенд)

- `POST /__test/scenarios` с параметрами `system`, `submissionOpen`, `appealOpen`,
  `finishExpired`, `quota`, `admitted`, `storageAvailable` создаёт изолированные
  игру, две команды, три задачи, восемь QR и восемь уже принятых ответов-заготовок.
- `PATCH /__test/scenarios/{gameId}` обновляет только внешние условия этого сценария.
- `GET /__test/events?gameId=...` возвращает сообщения, принятые стендом.
- `GET /__test/images?gameId=...` возвращает сохранённые изображения.
- `PUT /__test/event-sink` `{available}` включает/выключает приём сообщений.

Дедлайны вычисляются относительно времени создания сценария. Открытые сроки —
через час, закрытые — час назад. Это не значения production-настроек.
Для тестирования задержанной доставки у заготовок `acceptedAt` лежит до дедлайна.
Строка `fixture-signed:<UUID>` имитирует результат проверки подлинности QR, но не
предлагается как способ подписи реального QR.
