# Кабинет сотрудников

Кабинет использует авторизацию OpenID Connect и обращается к трём API через один адрес. Укажите HTTPS-адрес кабинета в конфигурации и проксируйте его на порт 19184. В OpenID Connect зарегистрируйте адрес возврата /auth/callback на том же хосте.

| Переменная | Значение |
| --- | --- |
| STAFF_ORIGIN | Внешний адрес кабинета |
| STAFF_OIDC_ISSUER, STAFF_OIDC_CLIENT_ID | Сервер идентификации и клиент |
| STAFF_OIDC_CLIENT_SECRET, STAFF_OIDC_SCOPE | Секрет конфиденциального клиента и требуемые области доступа |
| STAFF_IDENTITY_URL | Полный URL метода проверки токена. POST принимает token и возвращает active, userId и roles |
| STAFF_IDENTITY_SERVICE_TOKEN | Сервисный токен при необходимости |
| STAFF_PLATFORM_URL, STAFF_PLATFORM_SERVICE_TOKEN | API владельца игр, задач и учётных записей и сервисный токен для трёх API |
| STAFF_DIRECTORY_URL | Полный URL каталога доступных турниров для токена сотрудника. Формат описан в src/types.ts |
| STAFF_MATERIALS_URL, STAFF_INTAKE_URL, STAFF_REVIEW_URL | Адреса трёх API при отдельном запуске |

Сервисы должны проверять те же токены доступа, которые выдаёт настроенный поставщик идентификации. Свойства ролей берутся из проверенного ответа сервера.

Для Compose используйте основной файл из deploy вместе с deploy/staff.compose.yml и передайте конфигурацию через окружение. Для отдельного запуска выполните npm ci, npm run build и npm start из каталога staff.

Кабинет сохраняет исходящие действия в браузере в профиле сотрудника. Разрешённые операции восстанавливаются после входа и появления сети. Для рабочих мест используйте один постоянный адрес кабинета.
