# Приём: требования к интерфейсу камеры

Сценарии приёмки интерфейса камеры. Интерфейс камеры — отдельный компонент; этот сервис реализует серверный приём.

1. Пока QR выбранного снимка не распознан, отправка заблокирована. Успешное
   распознавание в предыдущем кадре не разрешает отправить другой снимок.
2. После распознавания UI проверяет принадлежность/подлинность/дубликат через
   серверные возможности. Предварительная проверка не резервирует бланк:
   окончательное решение принимает сервер при отправке.
3. Наблюдатель видит снимок и подтверждает чёткость. Без подтверждения отправка
   заблокирована даже при читаемом QR.
4. Замена/повторная съёмка изображения сбрасывает результат распознавания и
   подтверждение чёткости; проверки повторяются для новых байтов.
5. На сервер передаются эти же байты и прочитанный qrToken. Сервер независимо
   повторяет декодирование, сверку, проверку подлинности и дубликата.
6. QR_UNREADABLE предлагает переснять; QR_MISMATCH — повторить считывание с
   выбранного снимка; INVALID_QR запрещает сдачу; BLANK_ALREADY_ACCEPTED сообщает
   о ранее принятом бланке. Обход клиентской блокировки не обходит серверную.
7. Рукописный номер/текст ответа не вводятся в интерфейсе. Задача определяется
   по бланку; если проверяющий не разберёт текст, он выберет «неверно».

Качество съёмки и освещение относятся к приёмке компонента камеры.
