# Трассировка ТЗ → тесты

Все Ixx находятся в `tests/acceptance.test.mjs`.

| ID | Требование |
|---|---|
| I01 | Фото и факт приёма сохранены до подтверждения |
| I02 | QR читаем и подлинный; ошибка не создаёт приём |
| I03 | Наблюдатель обязан подтвердить чёткость |
| I04 | Один бланк принимается один раз |
| I05 | Конкурентные запросы не обходят запрет дубликата |
| I06 | Идемпотентный повтор возвращает прежнюю квитанцию |
| I07 | После дедлайна новые ответы не принимаются |
| I08 | Команда должна быть допущена |
| I09 | Сбой сохранения фото не выдаёт квитанцию и не расходует бланк |
| I10 | Сбой доставки на проверку не теряет принятый ответ |
| I11 | Полный manifest включает все ранее принятые ответы |
| I12 | Закрытие учитывает ожидающую доставку |
| I13 | Роль проверяющего/организатора не даёт право приёма; гость не допускается |
| I14 | Администратор и сочетание ролей имеют соответствующие права |
| I15 | Подмена команды/игры в клиентском запросе запрещена |
| I16 | Пустое/невалидное изображение отклоняется |
| I17 | Чтение квитанций защищено от посторонних |
| I18 | Номер задачи связан с бонусным бланком заранее |
| I19 | Устаревшая версия режима приёма не закрывает актуальную |
| I20 | Поздний приём открывается в той же игре без сброса дубликатов |
| I21 | Проверка ответа не нужна синхронно для приёма |
| I22 | Закрытие до дедлайна не допускается этим техническим API |

| I23 | taskId и номер задачи приходят из доверенного реестра бланков |
| I24 | После поздней сдачи manifest включает старые и новые ответы |
| I25 | Новый тип игры не требует нового API приёма |
| I26 | Явное разрешение поздней сдачи имеет приоритет над прежним дедлайном |
| I27 | Сервер повторно считывает QR из снимка, отсутствие QR не расходует бланк |
| I28 | QR на фото и переданный token совпадают, подмена фото не принимается |
| I29 | Поздний приём закрывает администратор вручную, срок апелляций не сдвигается |
| I30 | Новый ID задачи не подменяет принадлежность исходного бланка |

I22 — проектная договорённость о маршруте синхронизации дедлайна, не запрет
администратору изменять срок во внешнем сервисе игры. Исключающая граница
дедлайна, crash/restart, отмена, конкурентные запросы и сохранение outbox проверяются
в tests/Olympiad.Intake.Tests и дополнительной проверке процесса в test:service.
UI камеры и фактическая разборчивость текста здесь не проверяются.
